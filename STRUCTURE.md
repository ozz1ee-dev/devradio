# Proposed repository structure

```
.
├── tracks/
│   ├── index.json                     # generated import index (metadata, sha256, audio_url, fingerprint)
│   └── <slug>/                        # one folder per accepted track; folder name == id
│       └── track.yaml                 # metadata, licence, attestation, audio_url and sha256
├── schema/
│   └── track.schema.json              # JSON Schema 2020-12 contract for track.yaml
├── examples/
│   └── track.yaml                     # copy-paste starting point for contributors
├── scripts/
│   └── validate.py                    # schema + licence + download + audio + duplicate validation
├── docs/
│   └── N8N-IMPORT.md                  # pull, verify and upload logic for the home-server n8n workflow
├── .github/
│   ├── PULL_REQUEST_TEMPLATE.md       # licence attestation and review checklist
│   └── workflows/
│       └── validate.yml               # PR-only validation; forks get no secrets
├── CONTRIBUTING.md                    # contributor workflow and audio requirements
├── TAKEDOWN.md                        # notice, removal timeline and remediation proposal
└── LICENSES.md                        # accepted licences, attribution format and Suno notes
```

## Notes

- `tracks/<slug>/` is the unit of review. One PR may add several track folders.
- Audio is not committed to the repository. `track.yaml` points at a public HTTPS `audio.audio_url`
  and declares the matching `audio.sha256`; the file itself is downloaded by CI and later by the
  importer.
- `tracks/index.json` is generated by `python scripts/validate.py --all --update-index`. It lists the
  imported tracks with `id`, `title`, `artist`, `licence`, `source_url`, `sha256`, `audio_url` and
  `fingerprint`, so duplicate checks and the n8n importer do not need to rediscover tracks.
- `.github/workflows/validate.yml` uses `pull_request`, never `pull_request_target`, so fork code
  cannot read repository secrets. It downloads each submitted file from `audio.audio_url`, verifies
  `audio.sha256`, and runs the existing audio checks.
- After merge, GitHub does not contact the playout server. The n8n workflow on the owner's home server, in
  the **devradio** folder, polls `tracks/index.json` on the default branch, deduplicates by
  `sha256`, downloads new tracks, verifies the checksum and uploads them to the station
  media folder. All playout-server and SFTP credentials live only in n8n credentials.
- The station media folder is the single copy of the broadcast library. Back it up on a schedule
  and test restores; see [docs/N8N-IMPORT.md](docs/N8N-IMPORT.md).

## Website

The public site lives in `site/` (Astro). `.github/workflows/pages.yml` builds it and can deploy
to GitHub Pages after Pages is enabled. Stream, public player, and now-playing URLs are only in
`site/src/config.ts`. The credits section is rendered from `tracks/index.json` at build time.
No workflow calls the playout server. The browser asks the public now-playing URL itself and shows an
offline state when that request fails.
